# 26.1.2 Fabric Sodium / Iris クライアントゲームテスト終了コード調査

## 再現結果と直接原因

PowerShell からプロパティ引数を分割せず渡して実行した。

```text
gradlew.bat :26.1.2-fabric:runClientGameTest -Pcta.compat=sodium
gradlew.bat :26.1.2-fabric:runClientGameTest -Pcta.compat=iris
```

両構成とも、修正前の初回再現では `[client-test] RESULT: PASS` の直後に Gradle が `Process ... finished with non-zero exit value 1` で失敗した。Sodium 実行時の `versions/26.1.2-fabric/build/run/clientGameTest/logs/latest.log` では 245 行目が `RESULT: PASS`、246 行目が Fabric クライアントゲームテスト API の例外、247 行目が `IllegalStateException: Global terrain uniforms have not been updated`。248 行目から Sodium の `UniformBufferManager.getUniformBuffer` が例外元として記録され、260 行目に Fabric API の `ClientGameTestContextImpl.doTakeScreenshot`、269〜271 行目に MOD のスクリーンショット呼び出しと `AimScenario` の最初の撮影が続く。

この `PASS` はシナリオ完了を意味していなかった。`FabricAimGameTest.runTest` は例外時にも `finally` から `scenario.writeResults()` を実行し、例外を `scenario.failures()` に記録していなかったため、最初のスクリーンショットで中断したシナリオを誤って `PASS` と出力していた。撮影中の `GameRenderer.render` で Sodium が未更新の terrain uniform を拒否し、Fabric API のテストスレッドに例外を返してゲームプロセスを終了させていた。

Iris 構成でも同じ `Global terrain uniforms have not been updated` が発生した。Fabric API のスクリーンショット描画と Sodium の呼び出しの間に Iris の `LevelRenderer` terrain-layer wrapper がスタックに加わる。Iris がある場合も、失敗箇所は同じ最初のスクリーンショットである。

`versions/26.1.2-fabric/build/run/clientGameTest/crash-reports/` にクラッシュレポートはなく、ログには Fabric API のテスト例外と `Minecraft has crashed!` が記録された。再現時の依存構成は Sodium `0.9.2+mc26.1.2`、Iris `1.11.4+mc26.1.2`、Fabric API `0.155.3+26.1.2`、Fabric client game test API `5.1.0+0a5283664c`。

## 結論と修正

描画例外は Sodium 内で発生し、Fabric API の `takeScreenshot` がゲーム描画を実行した際に表面化する。MOD のテストはシーン準備で透明化を無効にした後の最初の撮影で止まっており、MOD の透明化描画処理が実行された段階ではない。この証拠から、終了コード 1 の直接原因は MOD の描画実装ではなく、26.1.2 の Fabric client game test screenshot と Sodium（Iris 使用時は Iris の描画 wrapper も含む）の組み合わせと判断した。MOD 側から失敗を回避する処理は加えていない。

テストコードだけを最小修正した。`FabricAimGameTest` は `RuntimeException` / `Error` を `scenario.failures()` に記録してから同じ例外を再送出し、`finally` の結果出力が中断を `RESULT: PASS` と偽表示しないようにした。例外や Gradle の終了コードは握りつぶさない。

## 修正後の確認

ゲームウィンドウを開くテストは1本ずつ実行した。

| コマンド | 終了コード | `latest.log` の結果 |
| --- | ---: | --- |
| `gradlew.bat :26.1.2-fabric:runClientGameTest -Pcta.compat=sodium` | 1 | `RESULT: FAIL (1)`（当該ログ232行目）。233行目から同じ Sodium 例外。 |
| `gradlew.bat :26.1.2-fabric:runClientGameTest -Pcta.compat=iris` | 1 | `RESULT: FAIL (1)`（当該ログ252行目）。253行目から同じ Sodium 例外、263行目に Iris wrapper、272行目に Fabric API の screenshot 呼び出し。 |
| `gradlew.bat :26.1.2-fabric:runClientGameTest` | 0 | `RESULT: PASS`（最新ログ260行目）。 |
| `gradlew.bat :26.3-fabric:runClientGameTest` | 0 | `RESULT: PASS`（最新ログ265行目）。 |

修正後の Sodium / Iris は引き続き終了コード 1 となる。これは外部描画・ゲームテスト API の例外を隠さないためであり、これらを0にする修正はしていない。各起動で専用実行ディレクトリが再作成されるため、ここに記した失敗時ログの行は各実行直後に採取したもの。後続の MOD 単体実行によって 26.1.2 の `latest.log` は置き換わっている。

## 追加調査: 撮影順序の特定 (2026-09-27)

使用中の Fabric API `0.155.3+26.1.2` に含まれる client game test API `5.1.0+0a5283664c` の JAR を `javap -c -p` で確認した。`ClientGameTestContextImpl.lambda$doTakeScreenshot$1` は `GameRenderer.extract(deltaTracker, true)` の直後に `render(deltaTracker, true)` を呼び、両者の前に `GameRenderer.update()` を呼んでいない。使用中の Sodium `0.9.2+mc26.1.2` の `UniformBufferManager#getUniformBuffer()` も、uniform データが null ならログと同じ `Global terrain uniforms have not been updated` を投げる実装だった。

[Fabric API issue #5466](https://github.com/FabricMC/fabric-api/issues/5466) には同じ例外と `doTakeScreenshot` のスタックが報告されている。同報告によると、通常の描画では `GameRenderer.update()` → `LevelRenderer.update()` → terrain のカリング・uniform 更新 → `extract()` の順になるが、Fabric API の撮影処理は `update()` を省いている。[Sodium PR #3788](https://github.com/CaffeineMC/sodium/pull/3788) で 26.1.2 に移植された uniform 処理が、この順序を前提にしている。今回のローカル JAR とログは、この既知の不整合に一致する。

Fabric API 側の修正候補は、撮影時の `extract()` より前に `gameRenderer.update(deltaTracker, true)` を呼ぶこと。これは上流 issue の提案であり、このリポジトリでは適用・検証していない。テストドライバからの追加呼び出しや別の撮影方式も未検証のため、現時点では回避策として扱わない。配布用 MOD の描画処理を変える根拠は見つからなかった。

`-Pcta.compat=iris-shader` は同じ Minecraft 26.1.2 と Sodium 0.9.2 を使うが、保存済みの `build/test-logs/26.1.2-fabric-iris-shader.log` では `Using shaderpack: cta_test_pack` の後に `RESULT: PASS` となっている。シェーダー有効時に失敗を避けられる理由は、今回のスタックとバイトコードだけでは特定できない。パック無しの Iris 構成を検証済みとみなす根拠にはならない。

## 残る影響

26.1.2 Fabric + Sodium / Iris (パック無し) のクライアントゲームテストは最初の撮影で中断し、透明化の視覚的な確認まで進めない。通常プレイで同じ経路を通るかは未確認。現行の `RESULT: FAIL (1)` は中断を正しく表している。
