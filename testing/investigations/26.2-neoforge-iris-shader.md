# 26.2 NeoForge + Iris + シェーダーパックのクラッシュ調査

## 環境

- Minecraft 26.2 / NeoForge 26.2.0.88
- Iris 1.11.4+mc26.2 (NeoForge) / Sodium 0.9.2+mc26.2
- Java 25.0.2、NVIDIA GeForce RTX 3060

## 再現

```powershell
& .\gradlew.bat ':26.2-neoforge:runSelfTest' '-Pcta.compat=iris-shader'
```

結果はクラッシュ。Iris が `cta_test_pack` を読み込んだ後、最初のワールド描画で発生し、SelfTest の `RESULT` 行には到達しなかった。例外は `ArrayIndexOutOfBoundsException: Index 1 out of bounds for length 1` で、スタックは次の順に遡る。

```text
GlCommandEncoder.validateDraw (Iris の MixinGlCommandEncoder)
GlRenderPass.drawIndexed
PreparedRenderType.drawFromBuffer (Iris の MixinPreparedRenderType)
FeatureRenderDispatcher$PreparedFrame.executeTranslucent
FeatureRenderDispatcher.renderAllFeatures
Iris HandRenderer.renderSolid
Iris の LevelRenderer.beginTranslucents hook
```

実行時のログには `Using shaderpack: cta_test_pack` があり、NeoForge の crash report でも同じ例外とフレームを確認した。`runSelfTest` は毎回実行ディレクトリを消すため、後続の比較実行時にこの実行ログと crash report は残らない。

## 切り分け

1. `buildSrc/.../ClearAimEras.kt` の 26.2 (e3) 用 Mixin リストを一時的に空にして、同じ `iris-shader` コマンドを実行。全 Clear Third Person Aim Mixin が有効でないことを生成済み mixin 設定で確認した状態でも、同じ `validateDraw` の例外でクラッシュした。Mixin 無効の診断実行ではシェーダー無しのゲームテストも実行したが、描画フックが無効なため `RESULT: FAIL (10)` となった。この失敗は通常構成の回帰ではない。
2. テストパックに一時的な `gbuffers_hand.vsh` / `.fsh` を追加し、1 と同じ状態で再実行。クラッシュは変わらなかった。ファイルは調査後に削除した。Iris の[プログラム仕様](https://github.com/IrisShaders/docs/blob/main/src/content/docs/current/Reference/Programs/gbuffers.mdx)では `gbuffers_hand` がプレイヤーの手と手持ちアイテムを描画し、未定義時の fallback が定義されているため、このプログラムの単純な欠落だけを原因とはできない。
3. Mixin リストとテストパックを元に戻し、シェーダーパック無しで `:26.2-neoforge:runSelfTest -Pcta.compat=iris` を実行。`RESULT: PASS`。
4. 元のテストパックを使い、`:26.2-fabric:runClientGameTest -Pcta.compat=iris-shader` を実行。`RESULT: PASS`。

## 結論と修正

この MOD の Mixin／合成処理は原因ではない。すべての MOD Mixin を無効にした場合にも同一クラッシュが起き、手描画用プログラムを加えても結果が変わらず、Iris を入れた NeoForge でもシェーダーパック無しなら通り、同じ Iris とパックの Fabric 構成は通る。

以上から、原因は Minecraft 26.2 における Iris NeoForge 版のシェーダー有効時の手描画経路、または Iris と NeoForge の描画連携にある可能性が高い。Mixin を無効にした状態でもゲーム全体から MOD を取り除いた比較ではないため、Iris 単体の不具合とまでは断定しない。許可された変更範囲内に根拠のある MOD／シェーダーパック修正は見つからなかったため、回避コードや恒久的なシェーダーファイル変更は行わない。

## 確認結果

| コマンド | 結果 |
| --- | --- |
| `:26.2-neoforge:runSelfTest -Pcta.compat=iris-shader` (通常構成) | クラッシュ、`RESULT` なし (`validateDraw` の範囲外アクセス) |
| `:26.2-neoforge:runSelfTest -Pcta.compat=iris-shader` (全 MOD Mixin を一時無効) | 同じクラッシュ、`RESULT` なし |
| `:26.2-neoforge:runSelfTest -Pcta.compat=iris-shader` (一時 `gbuffers_hand` 追加、全 MOD Mixin 無効) | 同じクラッシュ、`RESULT` なし |
| `:26.2-neoforge:runSelfTest -Pcta.compat=iris` (Mixin 復元) | `RESULT: PASS` |
| `:26.2-fabric:runClientGameTest -Pcta.compat=iris-shader` (元のパック) | `RESULT: PASS` |
| `:26.2-neoforge:runSelfTest -Pcta.compat=iris` (全 MOD Mixin を一時無効) | `RESULT: FAIL (10)`。描画 Mixin が無効な診断実行のため、通常構成の判定には使わない |

## 残る影響と KNOWN_ISSUES.md 追記案

26.2 NeoForge で Iris 1.11.4 のシェーダーパックを有効にすると、この環境ではクライアントテストが描画中にクラッシュする。パックを無効にした Iris 構成と Fabric 構成は PASS。上流側の修正までは本 MOD 側の安全な回避策を確認できていない。

追記する場合の文案:

> Minecraft 26.2 NeoForge と Iris 1.11.4 の組み合わせでは、シェーダーパック有効時に Iris の手描画中に `GlCommandEncoder.validateDraw` の `ArrayIndexOutOfBoundsException` が起きる環境がある。Clear Third Person Aim の Mixin を無効にしても再現し、Iris のシェーダーパック無しでは再現しない。パックを無効にするか、Iris 側の修正を待つ。
